Three of those 28, **R02 to R04**, were re-scored on 8 October with the two scoring problems repaired (Section 6); the simulator gain survived. A completed run is not the same as a proven result.
- The **13 extra rows in Section 3 are supporting work**, often part of existing experiments. They are not 13 independent new research experiments.

The learned controller still beats both rule-based controllers on mean error and on time outside the operating range, with 95% ranges excluding zero; staged training is worse; all inputs beat camera-only. Simulator only. R05 label picking is a separate task and did not help.
- Start with [the consolidated status](#section-4-consolidated-status-of-all-36-original-ids), then [what remains to run](#section-5-what-remains-to-run-and-what-else-is-worth-testing), [the RL answer](#section-6-did-rl-give-a-useful-answer), and [write-up readiness](#section-7-can-we-write-and-submit-the-write-up).

Sections 1 to 3 retain the detailed before/after evidence. Section 1 is historical: its old conclusions must not be quoted as the current result. The latest review takes priority where a claim has been reopened.

Same table format as [13_Results_vs_Expected_6_Oct.md](13_Results_vs_Expected_6_Oct.md). **Section 1** is that table exactly as it was on 6 Oct 2026, 20:00 IST (before the improvement experiments of [improvements.md](improvements.md)). **Section 2** is the same table after them (7 Oct 2026, evening IST), one row per experiment, with every result that changed. Two rows are new (B02 modern model, input gate).

No fixed pass marks were set in advance (user rule), so "had to beat" is the reference number for the same test. Gaps carry 95% ranges (whole filename groups resampled) where one was computed. All paths are relative to the project folder `AI4S/`.
Scores: **AUC** = chip-photo ranking grade (0.5 = coin flip, 1 = perfect, higher is better); **count error** = nuclei per image the count is off by (lower is better); **F1@0.75** = outline match at strict overlap (higher is better); **review area** = area under the "bad photos found vs share reviewed" curve (0.5 = random, higher is better).

# SECTION 6: Did RL give a useful answer?

**RL means learning actions by trying them and receiving feedback. Here it was used for two different jobs: controlling simulated droplets and choosing photos to label.**

**Answer: yes for the simulated droplet control, and the gain survived the repaired comparison; no for the photo-label picker.** R01 to R04 concern simulated droplet control; no physical chip was tested. R05 uses real chip-photo data to study label selection.

**Why it was re-checked:** the first evaluation measured error against the next target at target changes (steps 100 and 200), and a shared random seed did not give different controllers the same target schedule. Both problems were confirmed in the code. The saved policies were therefore re-scored on 8 October, without retraining, in a repaired environment: identical target schedule, plant and noise random numbers for every controller; error against the target in force; 50 new scenarios; five training seeds averaged inside each scenario; 95% ranges from resampling whole scenarios.
